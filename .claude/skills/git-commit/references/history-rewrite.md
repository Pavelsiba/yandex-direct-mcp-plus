# Переписывание истории ветки

Пуш на свою личную ветку — свободно (бэкап + CI), `--force-with-lease` на ней дёшев.
Осторожность включается, когда ветка стала общей: открыт PR на ревью или её кто-то забрал.
`dev` — интеграционная, `main` — релизная: переписывание истории там — только по явной
просьбе пользователя. В `main` вдобавок не уходит ничего, кроме мерджа PR из `dev`.

«Не пушить, пока не доделал» — плохое правило: причина кривой истории — коммит незрелого
решения, а не пуш.

Если ветка уже запушена и fixup'ы делать поздно — схлопнуть soft reset'ом на родителя
первого коммита задачи и пересобрать. Дерево обязательно сверить со страховочной веткой:

```bash
git branch backup/<task> HEAD      # страховка
git reset --soft <родитель первого коммита задачи>
git diff backup/<task> --stat      # пусто = дерево не поехало
# пересобрать: код → commit, тесты → commit
git push --force-with-lease        # только по явной просьбе пользователя
```

## Осторожно с semantic-release

Версия и `CHANGELOG.md` собираются из сообщений коммитов при мердже `dev` → `main`.
Схлопывание веток до мерджа безопасно. После того как релиз прошёл, история уже
процитирована в чейнджлоге и в теге — переписывать её нельзя даже по просьбе: сначала
обсудить, чем это грозит опубликованному релизу.

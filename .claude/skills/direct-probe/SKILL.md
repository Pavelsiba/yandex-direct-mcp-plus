# Проба API Директа

Документация Директа неполна и местами расходится с поведением. Догадка о форме ответа,
зашитая в фикстуру, даёт зелёный тест на неверном контракте — худший вид ложно-зелёного.
Этот скилл — процедура, как выяснить форму эмпирически, не потратив денег.

## Песочницы больше нет

**С июля 2026 песочница Директа отключена.** Тестовой среды не существует: аккаунт
песочницы не создать, `api-sandbox.direct.yandex.com` контуром не является. Источник —
ответ поддержки Яндекс.Директа от 05.09.2026 на прямой вопрос; проверить эмпирически
нечем, потому что создание аккаунта — как раз то, что недоступно. Наблюдаемый симптом:
`error_code 513`, «Ваш логин не подключен к Яндекс.Директу».

Отсюда следствие, определяющее весь скилл: **любая проба идёт по боевому аккаунту**.
Переменная `YANDEX_DIRECT_SANDBOX` и эндпоинты `api-sandbox` — мёртвый переключатель,
опираться на него нельзя.

## Модель безопасности

Ключевой факт, который делает пробу возможной: **деньги тратит не вызов API, а работающая
кампания** — прошедшая модерацию, включённая и обеспеченная средствами. Кампания в
черновике показов не даёт и стоить не может. Значит опыты ставятся на отдельной кампании,
которая никогда не выходит из черновика.

Три круга, границы между ними не размываются:

| Круг | Что можно | Цена |
| --- | --- | --- |
| Чтение чего угодно | `get`, словари, отчёты по прошлым периодам | баллы API |
| Запись на **полигоне** | создать, изменить, удалить объекты полигонной кампании | баллы API |
| Всё остальное | — | запрещено |

«Всё остальное» — это любой пишущий вызов, целью которого не является полигон. Реальная
кампания не правится «чтобы посмотреть, что вернётся», даже если правка выглядит
безобидной и обратимой: минус-фраза, ставка, время показа — всё это немедленно меняет то,
за что аккаунт платит.

### Кампания-полигон

Заводит её пользователь, не ты. Инвариант, который делает её безопасной:

- `Status: DRAFT` — на модерацию не отправлялась ни разу;
- `State: OFF` — выключена.

**`moderate_ads` на полигон не звать никогда.** Это единственный вызов, который выводит
кампанию из черновика, и после него полигон перестаёт быть полигоном.

ID полигона держится в разговоре или в `CLAUDE.local.md`, а не в коде и не в отслеживаемых
файлах. Нет ID под рукой — спроси, не угадывай по списку кампаний.

### Проверка цели — обязательна перед первой записью

Читающим вызовом, глазами по ответу:

```bash
npx tsx --conditions=development -e "
  const { apiPost } = await import('./src/shared/api/client.ts')
  console.error(await apiPost('campaigns', 'get', {
    SelectionCriteria: { Ids: [/* ID полигона */] },
    FieldNames: ['Id', 'Name', 'Status', 'State']
  }))
"
```

Ждём ровно `Status: "DRAFT"` и `State: "OFF"`. Любой другой ответ — включая пустой
результат, `ACCEPTED`, `MODERATION` — **остановка**: цель не та, о которой договаривались.
Скажи пользователю, что увидел, и не пиши ничего.

Флаг `--conditions=development` обязателен и здесь, и дальше: без него `tsx` резолвит
`#shared/*` в `dist/` и исполняет прошлую сборку вместо исходников.

### Правила, которые не обсуждаются

- Пишущий вызов — **только по явной просьбе пользователя** и только на полигон. Разрешение
  на одну пробу не распространяется на следующую.
- Токен не логировать, в фикстуры не сохранять, в сообщения не вставлять. Запреты в
  `.claude/settings.json` и хук `deny-secrets.mjs` обходить нельзя ни в какой форме —
  сработавший запрет означает «остановиться и сказать», а не «переписать команду».
- Каждый вызов тратит **баллы API боевого аккаунта** — те же, что нужны для работы.
  Клиент печатает заголовок `Units` (`потрачено/остаток/лимит`) в stderr: смотри на него,
  в цикле пробу не гоняй.
- Удаление — только объектов полигона. `delete` по чужому ID необратим и не имеет
  подтверждения на стороне API.

## Процедура

### 1. Написать пробу как одноразовый скрипт

Не тест и не файл в `src/`. Клади в скретчпад сессии, а не в репозиторий — проба не должна
пережить задачу и попасть в коммит.

```ts
// <scratchpad>/probe.ts
import { apiPost } from "../src/shared/api/client.js"

const raw = await apiPost("keywords", "get", {
  SelectionCriteria: { CampaignIds: [/* ID полигона */] },
  FieldNames: ["Id", "Keyword", "Bid", "StatusClarification"]
})

// Сырой ответ целиком — форму придумывать не надо, она вот она.
console.error(JSON.stringify(raw, null, 2))
```

Запуск: `npx tsx --conditions=development <scratchpad>/probe.ts`.

**Почему `console.error`, а не `log`:** stdout занят транспортом MCP. В пробе это не
критично, но привычка полезная — в сервере вывод в stdout ломает протокол.

### 2. Снять ответ **сырой строкой**, а не разобранным объектом

Ключевой момент для этого проекта. Если проба логирует уже распарсенный объект, 19-значные
ID в нём **уже округлены** — и фикстура, снятая с такого вывода, зафиксирует испорченные
данные как эталон. Тест на потерю точности станет бессмысленным.

Когда проба про ID, деньги или что-то другое числовое и длинное — снимай **тело ответа как
текст**, до всякого разбора:

```ts
// Точная строка, которую вернул Директ, — её и кладём в фикстуру.
const res = await fetch(url, { method: "POST", headers, body })
console.error(await res.text())
```

Тот же принцип на стороне запроса: проверяя, что уходит, смотри на `body` строкой, а не на
объект до сериализации.

### 3. Превратить в фикстуру — вычистив аккаунт

Фикстура едет в тест рядом с кодом, не в отдельный каталог «фикстур на будущее». Клади
структуру ровно так, как её вернул Директ, урезав до полей, которые проверяешь.

Раньше здесь стояло «значения не переписывать»: настоящий ID из песочницы был ничей.
**Теперь любой ответ — данные боевого аккаунта, а репозиторий публичный.** Из фикстуры
удаляются логины, названия реальных кампаний и объявлений, тексты, номера телефонов,
адреса; ID заменяются на выдуманные.

Замена ID делается **с сохранением разрядности**: девятнадцать знаков остаются
девятнадцатью. Проверяется в этих тестах не конкретное число, а то, что величина больше
`Number.MAX_SAFE_INTEGER` и переживает круг без округления, — выдуманный `1234567890123456789`
годится для этого ровно так же, как настоящий, и ничего про аккаунт не рассказывает.

Дальше — обычный unit-тест по правилам скилла `new-tool`: подменённый `fetch` отдаёт
фикстуру, ассерты стоят на том, что хендлер отдал наружу.

### 4. Прибрать за собой

- Скрипт из скретчпада удалить.
- Временные изменения в `src/` откатить (`git checkout -- <файл>`, если он был чистым).
- **Объекты, созданные на полигоне, удалить или оставить осознанно.** Полигон, заросший
  мусором прошлых проб, перестаёт быть предсказуемой средой, и следующая проба начнётся с
  разбора того, откуда взялась группа `test-3`.

В репозитории от пробы остаётся только фикстура и, если находка того стоит, комментарий.

### 5. Записать находку

Поведение API, которое стоило времени, — это знание, которое иначе теряется:

- **Комментарий в коде** — там, где на него опирается решение, с датой пробы:
  `// Пробой 03.09.2026: v5 отдаёт Bid микроединицами даже в ответе get, хотя док молчит.`
- **Дейлик** — если находка меняла ход работы.
- **`docs/architecture.md`** — если находка задевает инвариант, а не один инструмент.

Формулировка «пробой ДД.ММ.ГГГГ установлено, что …» в этом проекте уже принята — так
написано про баг диалекта JSON Schema в SDK и про поведение lefthook. Держись её: дата
отличает проверенный факт от предположения, которое кто-то принял на веру.

## Что стоит проверять пробой

- **Форма ответа**: какие поля приходят, какие опциональны, что приходит вместо
  отсутствующего значения (`null`, пропуск ключа, пустой массив).
- **Единицы**: где микроединицы, а где уже валюта. Live v4 отдаёт баланс в валюте
  аккаунта — в v5 та же по смыслу сумма пришла бы микроединицами.
- **Ошибки**: v5 отдаёт ошибку запроса **телом с HTTP 200**. Per-item ошибки — в
  `*Results`, обрезанная выборка — в `LimitedBy`. Проба на заведомо неверных данных
  показывает реальную структуру всех трёх случаев — и она бесплатна: неверный запрос
  ничего не меняет.
- **Перечисления**: реальный набор значений статуса или типа. Но первоисточник здесь —
  WSDL (`curl -s "https://api.direct.yandex.com/v5/<service>?wsdl"`, отдаётся без токена),
  а проба лишь показывает, что встречается на практике.
- **Нормализация входа**: что Директ делает с присланным — обрезает ли пробелы, приводит
  ли регистр, сохраняет ли порядок. Выясняется только записью на полигон и чтением обратно.
- **Пагинация**: при каком объёме появляется `LimitedBy` и что именно в нём.

## Чего пробой не выяснить

Полигон — это кампания без показов, и всё, что живёт показами, ему недоступно: свежая
статистика, данные аукциона, прогнозы, поведение модерации, статусы после её прохождения.
Такие вопросы либо остаются открытыми, либо отвечаются наблюдением за реальными кампаниями
пользователя — читающими вызовами, без вмешательства.

Отдельно: **гонки и конкурентные изменения пробой не ловятся**. Условного обновления в v5
нет (ни версии, ни ETag), а полигон — аккаунт, в котором в тот же момент может работать
человек в веб-интерфейсе. Проба покажет, что вызов прошёл, но не докажет, что он безопасен
под параллельной правкой.

Если различие принципиально для задачи — скажи об этом прямо, а не выдавай результат
полигона за общий контракт.

# Проба API Директа в песочнице

Документация Директа неполна и местами расходится с поведением. Догадка о форме ответа,
зашитая в фикстуру, даёт зелёный тест на неверном контракте — худший вид ложно-зелёного.
Этот скилл — процедура, как выяснить форму эмпирически, не потратив денег.

## Безопасность — читать до запуска

**Песочница обязательна.** `YANDEX_DIRECT_SANDBOX=1` переключает эндпоинты на
`api-sandbox.direct.yandex.com` (v5) и `api-sandbox.direct.yandex.ru` (Live v4). Токен тот
же, данные изолированы, реальных трат нет.

**Правила, которые не обсуждаются:**

- Пишущий вызов против **боевого** аккаунта — только по явной просьбе пользователя и
  никогда «чтобы посмотреть, что вернётся». Пишущие инструменты тратят реальные деньги.
- Не уверен, куда смотрит токен, — **не запускай, спроси**. Проверить можно читающим
  вызовом (см. ниже), но убедись в значении `YANDEX_DIRECT_SANDBOX` до этого.
- Токен не логировать, в фикстуры не сохранять, в сообщения не вставлять. Хук
  `PreToolUse` в `.claude/settings.json` отбивает шелл-команды, трогающие `.env`.
- Каждый вызов тратит **баллы API**. Клиент печатает заголовок `Units`
  (`потрачено/остаток/лимит`) в stderr — смотри на него, не гоняй пробу в цикле.

**Проверка, что песочница правда включена** — читающий вызов и глазами по URL в логе:

```bash
YANDEX_DIRECT_SANDBOX=1 npx tsx -e "
  const { apiPost } = await import('./src/client.ts')
  console.error(await apiPost('campaigns', 'get', { SelectionCriteria: {}, FieldNames: ['Id','Name'] }))
"
```

Песочница пустая по умолчанию — пустой список кампаний это норма, а не ошибка.

## Процедура

### 1. Написать пробу как одноразовый скрипт

Не тест и не файл в `src/`. Клади в скретчпад сессии, а не в репозиторий — проба не
должна пережить задачу и попасть в коммит.

```ts
// <scratchpad>/probe.ts
import { apiPost } from "../src/client.js"

const raw = await apiPost("keywords", "get", {
  SelectionCriteria: { CampaignIds: [/* id из песочницы */] },
  FieldNames: ["Id", "Keyword", "Bid", "StatusClarification"]
})

// Сырой ответ целиком — форму придумывать не надо, она вот она.
console.error(JSON.stringify(raw, null, 2))
```

Запуск: `YANDEX_DIRECT_SANDBOX=1 npx tsx <scratchpad>/probe.ts`.

**Почему `console.error`, а не `log`:** stdout занят транспортом MCP. В пробе это не
критично, но привычка полезная — в сервере вывод в stdout ломает протокол.

### 2. Снять ответ **сырой строкой**, а не разобранным объектом

Ключевой момент для этого проекта. Если проба логирует уже распарсенный объект, 19-значные
ID в нём **уже округлены** — и фикстура, снятая с такого вывода, зафиксирует испорченные
данные как эталон. Тест на потерю точности станет бессмысленным.

Когда проба про ID, деньги или что-то другое числовое и длинное — снимай **тело ответа
как текст**, до всякого разбора:

```ts
// Точная строка, которую вернул Директ, — её и кладём в фикстуру.
const res = await fetch(url, { method: "POST", headers, body })
console.error(await res.text())
```

Тот же принцип на стороне запроса: проверяя, что уходит, смотри на `body` строкой, а не
на объект до сериализации.

### 3. Превратить в фикстуру

Фикстура едет в тест рядом с кодом, не в отдельный каталог «фикстур на будущее». Клади
ровно то, что вернул Директ, урезав до полей, которые проверяешь — но **не переписывая
значения**: настоящий 19-значный ID из песочницы ценнее выдуманного `"123"`.

Из ответа удалить: токен (его там быть не должно, но проверь), логины, любые реальные
идентификаторы аккаунта, если проба шла не в песочнице.

Дальше — обычный unit-тест по правилам скилла `new-tool`: подменённый `fetch` отдаёт
фикстуру, ассерты стоят на том, что хендлер отдал наружу.

### 4. Удалить пробу

Скрипт из скретчпада удалить, временные изменения в `src/` откатить
(`git checkout -- <файл>`, если он был чистым). В репозитории от пробы остаётся только
фикстура и, если находка того стоит, комментарий.

### 5. Записать находку

Поведение API, которое стоило времени, — это знание, которое иначе теряется:

- **Комментарий в коде** — там, где на него опирается решение, с датой пробы:
  `// Пробой 03.09.2026: v5 отдаёт Bid микроединицами даже в ответе get, хотя док молчит.`
- **Дейлик** — если находка меняла ход работы (скилл `daily`).
- **`docs/architecture.md`** — если находка задевает инвариант, а не один инструмент.

Формулировка «пробой ДД.ММ.ГГГГ установлено, что …» в этом проекте уже принята — так
написано про баг диалекта JSON Schema в SDK и про поведение lefthook. Держись её: дата
отличает проверенный факт от предположения, которое кто-то принял на веру.

## Что стоит проверять пробой

- **Форма ответа**: какие поля приходят, какие опциональны, что приходит вместо
  отсутствующего значения (`null`, пропуск ключа, пустой массив).
- **Единицы**: где микроединицы, а где уже валюта. Live v4 отдаёт баланс в валюте
  аккаунта — в v5 та же по смыслу сумма пришла бы микроединицами.
- **Ошибки**: v5 отдаёт ошибку запроса **телом с HTTP 200**. Per-item ошибки — в
  `*Results`, обрезанная выборка — в `LimitedBy`. Проба на заведомо неверных данных
  показывает реальную структуру всех трёх случаев.
- **Перечисления**: реальный набор значений статуса или типа. Директ добавляет их без
  предупреждения — отсюда обязательный fallback в getter-функциях.
- **Пагинация**: при каком объёме появляется `LimitedBy` и что именно в нём.

## Чего пробой не выяснить

Песочница — не боевой аккаунт: в ней нет накопленной статистики, часть методов ведёт себя
упрощённо, лимиты другие. Находка «в песочнице работает» не равна «в бою работает».
Если различие принципиально для задачи — скажи об этом прямо, а не выдавай результат
песочницы за контракт.

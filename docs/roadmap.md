11. [ ] **Токен добывает пользователь — вход из диалога не поддержан.** Сейчас сервер
    берёт готовый `YANDEX_DIRECT_TOKEN` из окружения, а README отправляет за ним
    регистрировать своё приложение и подавать заявку на доступ к API. Для постороннего это
    непроходимый шаг: заявку по документации подаёт **только разработчик**, а рассмотрение
    занимает от часа до трёх суток (в пик до семи дней). Пакет опубликован в npm, так что
    барьер стоит перед каждым, кто его поставит.

    Снимается одной нашей заявкой: одобрение привязано к `client_id`, и «с этим приложением
    сможет работать неограниченное число пользователей» (Урок 3, `doc/ru/access-request`).
    Баллы при этом тратит владелец токена, а не приложение — чужие пользователи наш суточный
    лимит не трогают (`doc/ru/concepts/units`).

    Схема входа — Authorization Code + PKCE без `client_secret`: `start_login` собирает ссылку
    на `oauth.yandex.ru/authorize` с `redirect_uri=https://oauth.yandex.ru/verification_code`,
    пользователь присылает показанный код в чат, `finish_login` меняет его на пару
    access/refresh и кладёт в `~/.config/…/credentials.json` (0600, атомарная запись). В чат
    попадает одноразовый код, а не секрет: без verifier, который не покидает процесс, он
    бесполезен. Права (`Яндекс.Директ`) и redirect URI у нашего приложения уже настроены —
    проверено 06.09.2026.

    Работа: домен `tools/auth` (`start_login`, `finish_login`, `auth_status`, `logout`) и
    `shared/auth` (PKCE, хранилище, обновление по refresh). Основной объём не в OAuth, а в
    том, что `getToken()` перестаёт быть синхронным чтением `process.env` — за ним
    асинхронными становятся `commonHeaders`, `apiPost`, `apiV4`, `apiReport`. Часы приходят
    параметром, `YANDEX_DIRECT_TOKEN` остаётся приоритетнее сохранённого входа (CI и
    текущий сценарий не ломаются).

    - [ ] Проба: примет ли Яндекс обмен кода без `client_secret` на нашем `client_id`.
      Схема рабочая — `mcp-yandex-direct` (askads) 1.5.1 делает ровно этот вход из диалога
      (`start_login` / `finish_login`) и кладёт пару в
      `~/.config/mcp-yandex-direct/credentials.json`; проверено 06.09.2026 вызовом их
      `auth_status`. Чем закрыт обмен — PKCE или зашитым секретом — снаружи не видно,
      поэтому пробу на нашем `client_id` всё равно делаем.
    - [ ] Текст ошибки 53 (`shared/api/errors.ts`) после этого станет неверным для
      большинства: «пропишите YANDEX_DIRECT_TOKEN» нужно будет заменить развилкой по
      источнику токена.

    Цена решения, принимаемая осознанно: доступ выдаётся **нашему** приложению, и его
    блокировка ломает работу у всех сразу; `refresh_token` на диске — бессрочный доступ,
    пока его не отозвали в Яндекс ID; `client_id` уезжает в опубликованный пакет открытым
    текстом (для публичного клиента это норма, но необратимо). Приложение не удалять ни при
    каких условиях — с ним уходит заявка.

12. [ ] **Остаток баллов не виден инструментом.** Units — расходуемый ресурс: их нехватка
    просто запрещает запросы, а суточный лимит зависит от активности кампаний. Сервер
    печатает заголовок `Units` в stderr (`shared/api/fetch.ts`), но модель его не видит и
    спланировать выгрузку не может. Нужен читающий инструмент «потрачено / остаток / лимит»;
    источник — тот же заголовок ответа, отдельного метода API не требуется. Рядом стоит
    `Units-Used-Login`: он называет, чей лимит списан, и на агентском токене это не то же
    самое, что владелец токена.

## Инфраструктура

Отдельным потоком, до фич: архитектура (`docs/architecture.md`), линтеры
(Biome, knip), хуки (lefthook, commitlint), обновление зависимостей
(zod v4, SDK 1.30, TypeScript 7 — сделано 03.09.2026), рефакторинг под
архитектуру, CI/CD, semantic-release.

**Разбор ответов Директа схемой zod — выборочно.** 05.09.2026 так сделан домен
`dictionaries`: имя справочника связано с типом записей, ответ проходит через
`parseApiResult` (`shared/api/parse.ts`), непроверенных утверждений о форме данных
не осталось. Остальные 49 инструментов по-прежнему объявляют форму ответа кастом.

Расширять не подряд, а там, где разбор что-то даёт: значение переиспользуется (кэш)
или на нём стоит логика. Где хендлер просто форматирует ответ и печатает, схема добавит
файлов и ни одной гарантии. Два условия обязательны в любом случае: `z.looseObject` —
Директ добавляет поля без предупреждения, и строгая схема превратит это в отказ
инструмента; никакого приведения ID — они приходят строками из `json-bigint` и такими
и остаются.

## Дистрибуция

Пакет опубликован в npm, но ни в одном каталоге серверов его нет — при том что для
Директа там уже лежат чужие (06.09.2026: `io.github.askads/mcp-yandex-direct` и
`io.github.ai-hub-open/yandex-direct-mcp`).

- [ ] **Официальный реестр MCP** (`registry.modelcontextprotocol.io`): `server.json`,
  поле `mcpName` в `package.json`, публикация через `mcp-publisher` с GitHub OIDC.
  Обязательно частью релизного workflow, а не руками: у askads запись висит на 1.1.1
  при npm 1.5.1 — ручная публикация протухла за четыре релиза.
- [ ] **Glama** (`glama.json`): каталог индексирует серверы сам, файл нужен только чтобы
  закрепить право править карточку. Схема — одно поле `maintainers`.
- [ ] **README как продуктовая страница.** Сейчас он открывается таблицей переменных
  окружения; человек выбирает сервер по первому экрану. Сценарии вперёд, установка ниже.
  Делать **после** входа из диалога (пункт 11) — пока первый шаг требует своей заявки на
  доступ к API, витрина только приведёт людей к этой стене.

14. [ ] **Hosted-сервер — берём, но не первым и не в прежнем виде.** Прежняя формулировка
    («не берём: инфраструктура, аптайм и чужие токены ради режима только чтение») отменена
    06.09.2026 как неверная по двум пунктам сразу.

    Отменяет её аудитория. Барьеров на входе четыре: заявка на доступ к API, добыча токена,
    установка (Node, пакет, правка `mcp.json`) и способность клиента в stdio. Пункт 11
    снимает первые два и **не трогает** третий и четвёртый. Маркетолог, работающий из
    claude.ai в браузере или с телефона, к stdio-серверу не подключается никак — там только
    remote-коннекторы. Эту часть аудитории закрывает исключительно хостинг.

    Режим «только чтение» отменяется вместе с ней: статистику человек посмотрит в интерфейсе
    Директа, ценность сервера — в рутине (сборка кампаний, объявления, минус-слова, ставки).
    Хостинг без записи — не урезанный продукт, а никому не нужный.

    Граница проходит не по «чтение/запись», а по **скорости траты денег**. Пока кампания не
    прошла модерацию и не включена, показов нет и бюджет не тратится — на это уже опирается
    процедура полигона. По этой границе из 27 пишущих инструментов 20 идут без гейта
    (создание кампаний, групп, объявлений, ключей, минус-фраз, быстрых ссылок, визиток,
    изображений, расписания, целей); гейт нужен семи: `manage_campaigns` (`resume`),
    `manage_ads` (`resume` / `moderate` / `delete`), `moderate_ads`, `update_campaign`
    (бюджет), `set_keyword_bids`, `set_bid_adjustments`, `set_strategy`. Гейт — подтверждение
    через elicitation, а не запрет: тот же приём, что `mode` без умолчания у минус-фраз.

    Токены чужие, поэтому на диск не ложатся: OAuth 2.1 по спеке remote MCP, рукопожатие
    делает клиент, токен живёт в сессии. Мы прокси, а не хранилище.

    Стадии размещения: личный контур — контейнер на любом своём сервере, токен свой, риск
    свой; перед первым посторонним пользователем — отдельный инстанс. Причина переезда не в
    качестве изоляции контейнера, а в том, что с этого момента взлом соседа по хосту стоит
    чужих денег. Код от размещения не зависит — это смена хоста в деплое.

    Порядок: README (пункт выше) → 11 → бандл `.mcpb` для Claude Desktop (снимает барьер 3
    без хостинга: установка в одну кнопку, рантайм внутри, секреты в keychain ОС) → hosted.
    Пункт 11 не альтернатива хостингу, а его первая половина: тот же код OAuth плюс перенос
    токена из процесса в контекст сессии. Написанный позже — пишется дважды.

    Разведка 06.09.2026. У askads два контура. Пакет `mcp-yandex-direct` 1.5.1 — локальный
    stdio (`bin`, зависимости только SDK и zod, credentials на машине пользователя); вход из
    диалога есть — проверено вызовом их `auth_status`, барьеры 3 и 4 открыты.

    Их **hosted** — `https://mcp.askads.ru/mcp` — проверен вручную 06.09.2026 с телефона по
    мобильной сети: подключается, авторизация проходит, данные аккаунта отдаёт. Записи в нём
    нет, README не преувеличивает («только для чтения — статистики, аудита и просмотра
    объектов», «он не меняет настройки рекламы»). Вход — OAuth в браузере, токен в конфиг не
    передаётся: схема «токен в сессии, а не на диске» у них работает, значит выполнима.

    Размеры, посчитанные по факту: их пакет — 44 инструмента, их hosted — 20, у нас 51, из
    них 24 на чтение. То есть на удалённый контур они вынесли чтение и авторизацию, оставив
    все 24 пишущих в локальной установке. Следствие для витрины: **наш набор только на
    чтение уже больше, чем весь их hosted целиком**, и разрыв не только в записи — у них нет
    временного таргетинга и часовых поясов, чтения минус-фраз и общих наборов, `get_changes`,
    отчёта по поисковым запросам, ретаргетинг-листов, аудиторных и динамических целей, фидов,
    профилей организаций.

    Доступ отфильтрован по источнику. Сертификат в порядке (Let's Encrypt на `askads.ru` +
    `mcp.askads.ru` + `www`, 2026-06-30 — 2026-09-28, по CT-логам), но домен отвечает TLS
    alert 49 (`access_denied`) сразу после ClientHello — одинаково для curl, openssl и
    фетчера Claude из сторонней сети, тогда как с российского мобильного адреса через
    браузер всё работает. Похоже на геоблок или anti-bot по TLS-отпечатку. Отдельно и
    независимо тот же домен целиком блокирует ESET на рабочей машине — по репутации, со
    страницей про опасное содержимое.

    Для нашего хостинга это две статьи расходов, которых у пакета в npm нет вовсе: репутация
    нового домена (антивирусы массового рынка режут по спискам) и решение по фильтрации
    источников. Фильтр придётся ставить осознанно: он же отрезает часть легальных клиентов,

# CLAUDE.md

Указания для Claude Code при работе в этом репозитории.

## Что это

MCP-сервер (stdio) поверх API Яндекс.Директа v5: 51 инструмент — кампании, группы,
объявления, ключевые фразы, ставки, минус-фразы, временной таргетинг, статистика,
словари.

Первая версия собрана на коде `theYahia/yandex-direct-mcp` (MIT, расширение до 48
инструментов — DrSeedon, PR #7); дальше развивается самостоятельно, апстрим не
отслеживается. Атрибуция — в `LICENSE` и README.

- Архитектура и инварианты — `docs/architecture.md`. Читать до того, как решать,
  куда класть новый код.
- Пробелы в покрытии API и приоритеты — `docs/roadmap.md`.

## Команды

```bash
npm run build        # clean + tsc -p tsconfig.build.json → dist/
npm test             # vitest run
npm run test:watch
npm run dev          # tsx src/index.ts, без сборки
npm run lint         # biome check (формат + линт)
npm run lint:fix     # biome check --write
npm run typecheck    # tsc --noEmit: src, тесты и конфиги
npm run lint:dead    # knip
```

После правок исходников — `npm run build`: MCP-клиенты запускают собранный
`dist/index.js`, а не TypeScript.

Два конфига TypeScript, и это не дублирование: `tsconfig.json` ничего не собирает
и покрывает всё (`src`, тесты, конфиги) — по нему идёт `typecheck` и живёт редактор;
`tsconfig.build.json` наследует его, добавляет `rootDir`/`outDir` и исключает тесты.
Одним файлом это не сходится: сборке тесты не нужны, проверке типов — обязательны,
иначе они не проверяются ничем (vitest срезает типы через esbuild без проверки).

## Архитектура — коротко

```text
src/
  app/            композиция: сервер, реестр инструментов, точка входа
  tools/<домен>/  schema.ts (контракт) · handler.ts (сценарий) · tool.ts (дескриптор)
  shared/api/     клиент v5 / v4 / отчёты, retry, разбор ошибок
  shared/lib/     money, id, pagination, format, date, report, tool (defineTool)
  shared/config/  эндпоинты, окружение, лимиты, перечисления
  testing/        подмена fetch для тестов, в сборку не попадает
```

Границы слоёв объявлены subpath imports в `package.json`: `#shared/*`, `#tools/*`,
`#app/*`, `#testing/*`. Внутри домена импорты относительные (`./schema.js`) — тогда
любой `#tools/**` внутри `src/tools/**` означает обращение к соседу, и это ловится
одним правилом.

Направление зависимостей — `app → tools → shared`: инструмент не импортирует
инструмент, `shared` не знает про `tools` и `app`. Сторожит `noRestrictedImports` в
`overrides` секции `biome.json`, по блоку на слой.

`npm run dev` обязан идти с `--conditions=development`: без флага `tsx` резолвит
подпути в `dist/` и исполняет прошлую сборку вместо исходников. Разбор — в
`docs/architecture.md`.

Новый инструмент = каталог в `tools/<домен>/`, дескриптор через `defineTool`, явный
импорт в `app/registry.ts`, тест рядом с кодом. Аннотация (`READ` / `WRITE` /
`IDEMPOTENT` / `DESTRUCTIVE`) выбирается по реальной природе операции — на неё
полагаются клиенты.

## Обязательные соглашения

**Деньги.** API оперирует микроединицами (сумма × 1 000 000), наружу сервер отдаёт и
принимает рубли. Вход конвертирует схема, выход — `format`. Хендлер на миллион не
умножает.

**ID — строки, всегда.** 64-битные ID Директа (19 знаков) не помещаются в `Number`
без потери точности. Наружу — десятичные строки через `idField`, внутрь — `BigInt`.
`z.coerce` на ID-полях запрещён: он принял бы уже округлённое число и превратил его
в правдоподобную строку. Разбор и сериализация JSON — только через `json-bigint` и
только в `shared/api`. Держит это GritQL-плагин Biome (`plugins/no-native-json.grit`);
исключения помечены в самих файлах строкой `// biome-ignore-all lint/plugin`.
Полный разбор — `docs/architecture.md`.

**Перечисления — `z.literal([...])`, не `z.string()`.** Схема для модели и есть документация:
допустимые значения обязаны быть типом, а не прозой. Описание поля — `.meta({ description })`
(zod v4; `.describe()` — легаси v3), текст ошибки — `{ error: "..." }`. Конвенции общие
с соседним проектом `more-shop`.

Значения берутся из WSDL сервиса, а не со страниц справочника: `curl -s
"https://api.direct.yandex.com/v5/<service>?wsdl"` отдаётся без токена и содержит
`xsd:enumeration`. Страницы врут — сверка 03.09.2026 дала для `Ads.get` два статуса
вместо пяти. Неполный литерал отклоняет валидный вызов, поэтому неподтверждённый
список остаётся `z.string()` с перечислением в описании. Разбор — `docs/architecture.md`.

**Ошибки.** v5 отдаёт ошибку запроса телом с HTTP 200; per-item ошибки лежат в
массивах `*Results`, обрезанная выборка — в `LimitedBy`. Всё это разбирает `shared`,
в хендлерах ошибки не обрабатываются.

**Язык.** Описания инструментов, `.describe()`, сообщения об ошибках, комментарии и
коммиты — на русском.

**Update = полная замена.** Многие поля Директа (`NegativeKeywords.Items`, сайтлинки,
привязки наборов) перезаписываются целиком. Прежде чем «добавить одну фразу» —
прочитать текущее значение и отправить объединённое.

**Детерминизм.** `Date.now()` и подобное внутри хендлера делают его непроверяемым;
такие значения приходят параметром или из подменяемого хелпера.

## Окружение

- `YANDEX_DIRECT_TOKEN` — обязателен.
- `YANDEX_DIRECT_LOGIN` — Client-Login, нужен для агентских токенов.
- `YANDEX_DIRECT_SANDBOX=1` — песочница (`api-sandbox.direct.yandex.com`), тот же
  токен, реальных трат нет.

Пишущие инструменты тратят реальные деньги на боевом аккаунте. Проверять их —
только в песочнице и только по явной просьбе.

## Git

**Ветка под задачу.** Работа не ведётся ни в `main`, ни в `dev` — под каждую задачу
заводится своя ветка, названная по типу коммита, который в ней будет:

```text
feat/time-targeting        новая возможность
fix/negative-keywords-merge  исправление
refactor/tools-layout      перекладка без смены поведения
chore/lint-toolchain       оснастка, зависимости, конфиги
ci/release-pipeline        сборка и выкат
docs/architecture          документация
```

Ветка ответвляется от `dev` и возвращается в `dev` через pull request. Запрет на
коммит в `main` и `dev` держит хук lefthook, а не память.

**Пушим только в `dev` и ветки задач.** Прямой пуш в `main` запрещён — локально в неё не уезжает
ничего, даже первый коммит при создании репозитория. `main` наполняется
исключительно мерджем pull request'а из `dev` на стороне GitHub; там же по этому
мерджу отрабатывает semantic-release (версия + CHANGELOG + тег).

Следствие: пока первого релиза не было, ветки `main` на GitHub может не быть вовсе —
это нормально, а не сбой.

**Коммитить и пушить — только по явной просьбе пользователя.** Задача вида «сделай
X» не является разрешением зафиксировать результат в истории: правки в рабочем
дереве и коммит — разные действия, второе спрашивается отдельно. Разрешение на один
шаг не распространяется на последующие.

Коммиты — conventional commits на русском.

## Подводные камни

- Тесты не ходят в сеть: `fetch` подменяется. Проверяем тело запроса к Директу и
  разбор ответа — там живут ошибки маппинга.
- Линтер и форматтер — **Biome**, не ESLint. Причина: `typescript-eslint` не
  поддерживает TypeScript 7 («does not support TS 7.0»), а его пир `<6.1.0` сидит
  в `@typescript-eslint/parser` и `typescript-estree`, так что подменой пакета это
  не обходится. У Biome собственный парсер на Rust, от версии TypeScript он не
  зависит вовсе. Обратно на ESLint — только вместе с откатом компилятора.
- Biome держит и конфиги: `files.includes` покрывает `src`, корневые `.js`/`.ts`
  и `.json`, включая `.vscode`. JSONC он не портит — комментарии `tsconfig.json`
  переживают `format` побайтово, проверено. Правило `noQuickfixBiome` заодно
  ловит устаревшие имена действий в `.vscode/settings.json`.
- Баг диалекта JSON Schema в `@modelcontextprotocol/sdk` (`mapMiniTarget` отдаёт
  `draft-7` вместо `draft-2020-12`) ломает клиентов со строгой валидацией. Пробоем
  03.09.2026 установлено, что от версии zod он не зависит: `draft-07` уходит и на
  3.25.76 + SDK 1.29, и на 4.5.4 + SDK 1.30. Описания полей при этом доезжают —
  и через `.meta({ description })`, и через легаси `.describe()`. При обновлении
  SDK пробой повторять: поднять сервер, вызвать `listTools`, посмотреть `$schema`.
